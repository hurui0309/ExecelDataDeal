## 二、优化方案与执行

### 修改文件：`data_to_db/strategies/strategy_multi_header.py`

### 修改1：向上扩展 header 范围

**位置**：`run()` 函数，在分类标题行裁剪之后、多行表头合并之前

**修改内容**：新增向上扩展逻辑，检查 header_start 上方是否有遗漏的部分表头行。

**判断规则**：
- 从 header_start-1 开始向上遍历
- 跳过空行
- 遇到标题行或分类行时停止
- 遇到含数字数据的行时停止（数据行不应纳入header）
- 其余有非空单元格的行视为部分表头行，纳入header范围

**效果**：
- 表1：header_start 从3扩展到2，纳入了"单"行 → "单位"合并正确
- 表2：header_start 从3扩展到2，纳入了"1988年为"行 → "1988年为1987年pct"合并正确

### 修改2：保留分类行在数据区

**位置**：`run()` 函数，auto_data_start > actual_data_start 的分支

**修改内容**：不再将 actual_data_start 跳至 auto_data_start，保留分类行在数据区，由 `_merge_indicator_column` 处理。

**原逻辑**：
```python
elif auto_data_start >= 0 and auto_data_start > actual_data_start:
    actual_data_start = auto_data_start  # 跳过分类行
```

**新逻辑**：
```python
elif auto_data_start >= 0 and auto_data_start > actual_data_start:
    # 保留分类行在数据区，由 _merge_indicator_column 处理
    pass
```

**效果**：
- 表1："一、农垦系统"分类行不再丢失，入库行数从14增至15
