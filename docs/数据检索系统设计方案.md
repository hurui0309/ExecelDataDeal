# 数据检索系统设计方案

> **最终目标**：根据用户的自然语言诉求（如"帮我查一下1985年各地区社会商品零售总额"），系统能够快速定位到需要检索哪张数据库表的哪些字段。

---

## 总体架构

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  第一阶段     │     │   第二阶段        │     │   第三阶段         │
│  语义提取     │ ──→ │   归纳汇总        │ ──→ │   智能检索         │
│  (离线批处理) │     │   (离线聚合)      │     │   (在线查询)       │
└──────────────┘     └──────────────────┘     └──────────────────┘
   逐 Excel/Sheet         跨表归纳                 用户输入诉求
   提取元数据             建立索引                 匹配表+字段
   大模型理解语义         汇总分类                 返回结果
```

---

## 第一阶段：语义提取（本期重点）

### 1.1 目标

逐个 Excel 文件的每个有效 Sheet，利用大模型提取表的语义信息和字段信息，并将结果结构化存储，形成可检索的元数据库。

### 1.2 整体流程图

```
扫描目录
  │
  ├─ 遍历所有 .xlsx/.xls 文件
  │
  └─ 对每个文件:
       │
       ├─ 1. 获取 Sheet 列表 (复用 data_to_db 的 list_sheets)
       │
       └─ 对每个 Sheet:
            │
            ├─ 2. 读取前 20 行预览 (复用 data_to_db 的 excel_preview.run)
            │
            ├─ 3. 说明页判断 (LLM 快速判断是否为纯说明/目录页)
            │      │
            │      ├─ 是说明页 → SKIP，不存储
            │      │
            │      └─ 否 → 继续
            │
            ├─ 4. 语义提取 (LLM 深度分析)
            │      输入: 前20行数据 + 路径信息 + Sheet名 + 总行列数
            │      输出: 表描述 + 字段语义 + 数据特征
            │
            └─ 5. 写入元数据表 (MySQL)
```

### 1.3 数据读取（复用现有能力）

直接复用 `data_to_db/services/excel_preview.py` 中的以下函数：

| 函数 | 用途 | 参考代码位置 |
|------|------|-------------|
| `list_sheets(file_path)` | 获取 Sheet 名列表、文件大小 | `excel_preview.py:16` |
| `run(file_path, sheet_index, preview_rows=20)` | 读取前 N 行预览数据、总行列数、合并单元格数 | `excel_preview.py:65` |

**为什么只需读前 20 行**：
- 前 20 行通常包含了表名标题行、表头行和足够多的数据样本
- 大模型可以通过前 20 行理解表的主题、字段含义、数据类型
- 参考现有 Classifier 的做法（`config.yaml:35`，`preview_rows: 20`），已经验证足够用于语义判断

### 1.4 主键设计

**主键：`Excel 文件路径 + Sheet 序号`**

```python
primary_key = f"{file_path}||{sheet_index}"
```

选择理由：
- 文件路径天然唯一（同一数据目录下）
- Sheet 序号在同一个文件中唯一标识一个 Sheet
- 相比 Sheet 名称更稳定（Sheet 名可能包含特殊字符或重名）
- 同时保留 Sheet 名称作为辅助信息

### 1.5 说明页过滤

直接复用现有 Classifier 的 SKIP 判断逻辑（`classifier.py:18`），规则如下：

**自动规则（无需 LLM）**：
- Sheet 名包含关键词：`必看说明`、`数据说明`、`使用说明`、`目录`、`前言`、`备注`、`附录`、`凡例`
- 全 Sheet 数据行数 ≤ 3 行

**LLM 辅助判断**（自动规则无法确定时）：
- 将前 20 行发给 LLM，让它判断是否为"纯说明/目录/备注页"
- Prompt 参考现有 Classifier 中的 SKIP 描述：`"目录/空文件/无有效数据/纯说明备注页（如仅含'搜索马克数据网'等说明文字，无表格结构）"`

### 1.6 语义提取 Prompt 设计

#### 输入信息

发给 LLM 的完整上下文包括：

```
你是一个数据表语义分析专家。请分析以下 Excel Sheet 的内容。

【文件路径】: {file_path}
【文件名】: {file_name}
【Sheet 名】: {sheet_name}
【Sheet 序号】: {sheet_index}
【总行数】: {max_row}
【总列数】: {max_col}
【合并单元格数】: {merged_count}

【前 20 行预览数据】:
Row0: ...
Row1: ...
...
Row19: ...

请分析这个表格的语义信息，包括：
1. 这个表格描述的是什么内容/主题
2. 每列的含义和语义描述
3. 数据的特征（如时间范围、地理范围、统计口径等）
```

#### 输出格式

要求 LLM 严格输出 JSON：

```json
{
  "table_description": "该表记录了1985年各地区社会商品零售总额，按地区和商品类别分类统计...",
  "table_category": "经济/零售/社会消费品",
  "table_keywords": ["1985年", "社会商品零售总额", "地区", "零售"],
  "time_range": {"start": "1985", "end": "1985", "granularity": "year"},
  "geo_coverage": "全国各省/地区",
  "measure_type": "金额",
  "row_count_estimate": 200,
  "fields": [
    {
      "column_index": 0,
      "column_name": "地区",
      "semantic_description": "地区名称，表示统计的地域范围",
      "data_type": "string",
      "is_dimension": true,
      "sample_values": ["全国总计", "北京", "天津", "上海"]
    },
    {
      "column_index": 1,
      "column_name": "社会商品零售总额",
      "semantic_description": "该地区的社会商品零售总额，单位为亿元",
      "data_type": "number",
      "is_dimension": false,
      "unit": "亿元",
      "sample_values": ["4305.0", "1275.0", "689.0"]
    }
  ]
}
```

**字段说明**：

| 字段 | 说明 | 用途 |
|------|------|------|
| `table_description` | 大模型理解的表内容描述（50-200字） | 第三阶段检索匹配 |
| `table_category` | 表的分类标签 | 第二阶段分类汇总 |
| `table_keywords` | 关键词列表 | 第三阶段关键词匹配 |
| `time_range` | 数据的时间范围 | 时间维度过滤 |
| `geo_coverage` | 地理覆盖范围 | 地理维度过滤 |
| `measure_type` | 指标类型（金额/数量/比率等） | 指标类型过滤 |
| `fields[].column_index` | 列序号（0-based） | 关联原始数据 |
| `fields[].column_name` | 列名（原始中文名） | 字段标识 |
| `fields[].semantic_description` | 字段语义描述 | 第三阶段字段匹配 |
| `fields[].data_type` | 数据类型预估 | 辅助判断 |
| `fields[].is_dimension` | 是否维度字段 | 区分维度和指标 |
| `fields[].sample_values` | 前几行的样本值 | 验证和辅助理解 |

### 1.7 元数据表设计

```sql
CREATE TABLE IF NOT EXISTS `ods_sheet_metadata` (
    `id`                    BIGINT AUTO_INCREMENT PRIMARY KEY,
    
    -- 主键标识
    `file_path`             VARCHAR(1024) NOT NULL COMMENT 'Excel文件完整路径',
    `sheet_index`           INT NOT NULL COMMENT 'Sheet序号(0-based)',
    `file_name`             VARCHAR(512) NOT NULL COMMENT '文件名',
    `sheet_name`            VARCHAR(512) NOT NULL COMMENT 'Sheet名称',
    
    -- 文件元信息
    `file_size_bytes`       BIGINT DEFAULT NULL COMMENT '文件大小(字节)',
    `max_row`               INT DEFAULT NULL COMMENT '总行数',
    `max_col`               INT DEFAULT NULL COMMENT '总列数',
    `merged_count`          INT DEFAULT NULL COMMENT '合并单元格数',
    
    -- LLM 语义提取结果
    `table_description`     TEXT COMMENT 'LLM生成的表内容描述',
    `table_category`        VARCHAR(256) DEFAULT NULL COMMENT '表分类标签',
    `table_keywords`        TEXT COMMENT '关键词列表(JSON数组)',
    `time_range_start`      VARCHAR(64) DEFAULT NULL COMMENT '时间范围起始',
    `time_range_end`        VARCHAR(64) DEFAULT NULL COMMENT '时间范围结束',
    `time_granularity`      VARCHAR(32) DEFAULT NULL COMMENT '时间粒度(year/month/day)',
    `geo_coverage`          VARCHAR(256) DEFAULT NULL COMMENT '地理覆盖描述',
    `measure_type`          VARCHAR(128) DEFAULT NULL COMMENT '指标类型(金额/数量/比率等)',
    
    -- 字段元信息(JSON格式，方便检索)
    `fields_json`           MEDIUMTEXT COMMENT '字段信息JSON数组',
    
    -- 处理状态
    `status`                VARCHAR(16) NOT NULL DEFAULT 'SUCCESS' COMMENT '处理状态: SUCCESS/SKIP/ERROR',
    `error_message`         TEXT DEFAULT NULL COMMENT '错误信息',
    `llm_model`             VARCHAR(64) DEFAULT NULL COMMENT '使用的LLM模型',
    `llm_time_ms`           INT DEFAULT NULL COMMENT 'LLM调用耗时(毫秒)',
    `total_time_ms`         INT DEFAULT NULL COMMENT '总处理耗时(毫秒)',
    
    `created_at`            DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`            DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    
    -- 唯一键：同一文件的同一Sheet只存一份
    UNIQUE KEY `uk_file_sheet` (`file_path`(255), `sheet_index`),
    -- 索引：按分类检索
    INDEX `idx_category` (`table_category`),
    -- 索引：按状态过滤
    INDEX `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Sheet语义元数据表';
```

    def __init__(self, config: dict):
        self.config = config
        self.llm_client = LLMClient(config)
        self.db_conn = None
    
    def run(self, data_dir: str):
        """主流程：扫描 → 逐Sheet提取 → 写入元数据表"""
        files = self._scan_files(data_dir)
        for file_path in files:
            self._process_file(file_path)
    
    def _process_file(self, file_path: str):
        """处理单个文件"""
        sheet_info = list_sheets(file_path)
        for si, sheet_name in enumerate(sheet_info['sheet_names']):
            # 1. 快速跳过判断
            if self._quick_skip_check(sheet_name):
                continue
            
            # 2. 读取前20行预览
            preview = run(file_path, si, preview_rows=20)
            
            # 3. LLM判断是否为说明页
            if self._is_skip_sheet(preview, file_path, sheet_name):
                continue
            
            # 4. LLM语义提取

### 1.10 性能考量

| 项目 | 预估 | 说明 |
|------|------|------|
| 单 Sheet 读取耗时 | ~100ms | 仅读前20行，远小于全量读取 |
| 单 Sheet LLM 耗时 | ~2-5s | 取决于模型和网络延迟 |
| 整体吞吐量 | ~600-1500 Sheet/小时 | 约 6-15 个文件/小时（假设每文件5个Sheet） |
| 数据库写入 | 瞬时 | 单条 INSERT，无批量写 |

**优化方向**：
- 并发调用 LLM（多 Sheet 并行提取）
- 增量处理（基于文件 mtime 跳过已处理的 Sheet）
- 说明页快速跳过（减少不必要的 LLM 调用）

## 第二阶段：归纳汇总（后续）

### 2.1 目标

基于第一阶段提取的元数据，对全量 Sheet 进行跨表归纳、去重、分类和索引构建。

### 2.2 计划实现

1. **表分类汇总**：按 `table_category` 汇总，生成分类目录树
2. **关键词索引**：基于 `table_keywords` 构建倒排索引
3. **字段级聚合**：按字段语义归类，识别"同一概念不同表不同名"的情况
4. **数据关联发现**：通过字段名和样本值相似度，发现跨表关联关系

### 2.3 输出

- 分类索引表（支持按主题浏览）
- 关键词倒排索引（支持关键词搜索）
- 字段语义同义词映射（"社会商品零售总额" ≈ "商品零售额" ≈ "零售总额"）

## 第三阶段：智能检索（后续）

### 3.1 目标

用户输入自然语言诉求，系统自动匹配最相关的表及其对应字段。

### 3.2 检索流程

```
用户输入: "帮我查1985年各地区社会商品零售总额"
         │
         ├─ Step 1: 意图解析 (LLM)
         │   提取: 时间=1985年, 地理=各地区, 指标=社会商品零售总额
         │
         ├─ Step 2: 关键词匹配 + 语义检索
         │   在 ods_sheet_metadata 中检索：
         │   - table_keywords 匹配 ("1985年", "零售", "地区")
         │   - table_description 语义相似度
         │   - time_range 时间范围匹配
         │
         ├─ Step 3: 字段级匹配
         │   在匹配到的表中，按 fields_json 中的 semantic_description
         │   找最匹配的字段
         │
         └─ Step 4: 返回结果
              {
                "matched_table": "ods_1985_social_retail_xxx",
                "matched_fields": [
                  {"name": "region", "description": "地区名称"},
                  {"name": "total_retail", "description": "社会商品零售总额(亿元)"}
                ],
                "confidence": 0.95,
                "query_suggestion": "SELECT region, total_retail FROM ... WHERE ..."
              }
```

### 3.3 可能的检索方式

| 方式 | 说明 |
|------|------|
| 关键词匹配 | 基于 `table_keywords` 做精确/模糊匹配 |
| 语义相似度 | 对 `table_description` 做向量检索（embedding） |
| 结构化过滤 | 按 `time_range`、`geo_coverage` 等结构化字段过滤 |
| 字段级检索 | 在 `fields_json` 中检索字段语义描述 |
